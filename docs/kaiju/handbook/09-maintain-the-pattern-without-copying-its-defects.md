# Maintain the pattern without copying its defects

Renovate proposes changes. It does not prove compatibility, perform a source merge or validate a user journey. Group
coupled application images and compatible SDK/provider cohorts. Test the actual installed package or built image.
Recheck the relevant service procedure when a dependency changes its request shape, platform, runtime or schema.

For owned source, retain actual ancestry or an explicit requested/integrated import record. OpenATS's importer proves a
full upstream source delta; editing a version marker alone is insufficient. Preserve customizations and resolve
conflicts from the verified base. Do not create a permanent fork when supported config or plugins cover the need.

Reuse the existing Kaiju GitHub tooling for generic setup, scanners, provider generation and runtime preparation.
Extract a new shared package only after its cross-project contract and real consumers are clear. Keep provider adapters
thin; keep application semantics local. New package publication must be an early named dependency with a consumer
verification step.

Check the selected shared-tooling revision's include paths and task/action inputs before copying configuration. The
reviewed Grafana and Twenty pins use `packs/<name>` paths; Core PR 552 uses `packs/<name>/tasks`. These are versioned
interfaces. Neither spelling is a universal correction for the other revision.

Each incident produces one owned prevention improvement: remove the unnecessary operation, encode the invariant, add a
cheap capability check, test the behavior, or document the remaining choice. The
[failure catalogue](../failures/README.md) supplies exact examples. A new prose warning alone is not closure for a
failure that can be prevented in code or configuration.

Close the fresh-install path too. Search every setup, recovery, audit and default that consumes the changed setting.
Decide whether a generic default remains valid or needs a host-specific condition. Rehearse the maintained instructions
from fresh configuration. A working production override cannot repair an old recipe that still recreates the failure.

External services can still fail. The required operating rule is that known prerequisites are checked before long
implementation, mandatory failures remain visible, and recovery follows a tested procedure. A green service record
applies only to its identity, environment, contract and recorded observation. Credential rotation, provider drift,
changed topology or a new client can invalidate it.
