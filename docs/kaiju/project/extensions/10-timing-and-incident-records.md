# Timing and incident records

Record these timestamps in one time zone: request accepted, first prerequisite report, prerequisites ready, checks
passing, preview ready, journey passed, release tagged, release published and each store state. Keep wait categories and
rework separately. Do not restart the original clock after the owner supplies access.

An incident record needs a stable name, commit and browser, first symptom, impact, confirmed cause or open hypothesis,
evidence, repair, result and prevention owner. Add it to the [failure catalogue](../../failures/README.md). A later green
run is useful evidence, but it does not by itself establish the cause of an earlier failure.
