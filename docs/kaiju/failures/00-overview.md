# Overview

Use this catalogue to identify the failing contract, preserve the evidence and choose the smallest repair. The entries
come from DeepScope's own history (`DS-*` identifiers). They include observed failures, build defects, verification
limits and recorded design risks. Each entry records the confidence in its cause separately from its repair status. A
merged fix, a passing test, a green workflow and a completed journey in a real browser are different evidence.

The complete shared handbook retains deployment examples from ItsAPlan and OpenATS, including Kubernetes, Bunny,
Tailscale, email and object storage, plus a retrospective coverage map. The [catalogue index](README.md#shared-incident-lessons)
links to those chapters. They explain failure patterns across projects; their presence does not establish a DeepScope
deployment or browser incident. Record local findings under `DS-*` with current source and runtime evidence. Use the
[extension procedures](../procedures/extensions/README.md) for this repository and [AE01–AE08](../agents/README.md)
for the recurring execution controls.
