# Read the original evidence with its limits

The original playbook was informed by supplied ItsAPlan and OpenATS reports. This split pack preserves the resulting
coverage and source links. Verify access to the original reports separately; a citation does not establish that their
attachments are embedded in this release.

Report IDs such as **IAP report P01** and **OA report A02** refer to the supplied inventories. They are different from
procedure P01 and catalogue entry IAP-01. The labels below preserve that distinction.

Each row supplies a documented prevention/detection rule, owner and evidence requirement. **Documentation coverage is
complete; organization-wide automation and live rehearsal are not implied.** Bind the rule to the actual repository
command. When no executable check exists, keep it as an explicit operator step or automation gap. Historical code fixes
retain only the scope proved by their linked evidence.

The sources include direct source findings, user confirmations, explicit agent admissions, historical agent reports,
near misses and hypotheses. Do not flatten those into one confidence level. In particular:

- The ItsAPlan report says Carl granted Actions Read for the twelve-package cohort. Current exact-source CI success is
  independently verified; the administrative action is attributed historical evidence.
- The OpenATS report confirms one authorized deployed invitation's Resend event and inbox arrival on port 2587. It does
  not prove password setup, every recipient or the exact packet-filtering mechanism.
- The self-referencing CNAME and hidden-artifact issues were caught before the alleged outage. The dangerous Web push
  was stopped; the records do not establish loss of the ten newer commits.
- Later requested branding, AI and OAuth work was legitimate added scope. The ItsAPlan SDK work is not established as
  unauthorized. Refused login, real permission boundaries, provider limits and deliberate review stops are not agent
  misconduct.
