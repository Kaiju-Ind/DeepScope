# Generic project profile

This is the default. Start with the customer's goal and the [product question](../product/README.md), then use the
project's verified source, tooling and constraints. The method also works for an API, library, command-line program,
internal workflow, mobile application or product research task. A web preview or production deployment is required only
when the agreed outcome calls for one.

Fill only the applicable fields in the existing [project contract](../project/01-project-identity-and-first-value.md).

| Bind from current evidence | Record |
| --- | --- |
| Customer and outcome | Intended audience, first useful action, problem and decision to enable. |
| Source and authority | Exact repository or source set, branch/revision, current instructions, applicable skills and owned scope. |
| Runtime and tooling | Installed versions, supported environments, native commands and supported public APIs. |
| Dependencies | Existing maintained packages, public exports, access constraints and verified consumer behavior. |
| Experiments | Earliest useful test, baseline, controls, metrics, allowed effects and cleanup. |
| Delivery | Required artifact or user journey, acceptance evidence, deployment only if requested, and recovery. |
| Owners | Decision owner, implementation owners, reviewers and any external prerequisites. |

Use an existing repository's architecture, package manager and task runner unless the requested work or a demonstrated
limitation requires a change. Do not add Kubernetes, Bunny, Deno, Mise, private Kaiju packages, a monorepo layout, an AI
provider or a deployment system because a worked example contains one. The runtime-specific skills and service cards
apply only when their contracts are part of the task.

Keep reusable principles from historical examples: verify the true consumer, separate source from installed artifacts,
measure relevant outcomes, preserve failed evidence, maintain ownership, and carry an honest continuation. Refresh
provider behavior and source identities before executing an example's command. Historical success is not current
acceptance evidence.
