# The first action is an intake, not a scaffold

Read the repository's current instructions and actual remote branch. Define one journey that a reviewer must complete.
Classify each component as an upstream image, a published JavaScript package/file, or owned source. Then choose
Kubernetes-only or Bunny plus Kubernetes placement.

Before substantial implementation, give Carl the known actions that only he or another administrator can complete. Name
exact packages, versions, repositories, account permissions, domains and environments. Include package publication or a
controlled CI generation job if either is required. Continue independent work while those actions are completed. Report
newly discovered blockers immediately.

Maintain one [active task record](../agents/00-overview.md) with the outcome, accepted decisions, current source,
authorization, evidence, next action and continuation. Reconcile it with the latest user message before resuming work.
Use the task's relevant controls; the retrospective is a coverage reference, not 85 forms to complete for every
application.

Use the current original skills and guides. This pack routes deployment work; it does not replace repository rules or
grant permission to publish packages, send messages, spend money or change a live system. Existing authorization remains
valid. Do not ask for it again.
