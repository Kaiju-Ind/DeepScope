# The first action is an intake, not a scaffold

Read the repository's current instructions (`AGENTS.md`), the plan that owns the work under `docs/migration/`, and the
actual branch and its base. Define one journey that a reviewer must complete in the built extension, and name the
browsers it covers. Classify each component the change touches: owned source, a vendored `@utils/*` package, an npm
dependency, or generated output (registry files, `.wxt/`, `.output/`).

Before substantial implementation, give the owner the actions that only they can complete: a licence choice, catalog
redistribution rights, a store account or listing, an Apple Developer Program membership, repository settings
(immutable releases, tag rules, environments), or a credential stored as an environment secret. Continue independent
work while those actions are completed. Report newly discovered blockers immediately.

Maintain one [active task record](../agents/00-overview.md) with the outcome, accepted decisions, current source,
authorization, evidence, next action and continuation. Reconcile it with the latest user message before resuming work.

Use the current skills and guides. This playbook routes the work; it does not replace repository rules or grant
permission to push, tag, publish a release or submit to a store. Existing authorization remains valid. Do not ask for it
again.
