# The first action is an intake, not a scaffold

Read the current repository instructions, applicable original skills and guides, actual source revision and existing
task record. Establish who is affected, the desired outcome, the current obstacle and the decision to make. Preserve
current work and existing authorization.

Apply [A01](../product/01-a01-start-from-the-product-question.md) before substantial implementation. Extract known
questions from the request and source, add material missing dependencies, and identify plausible alternatives. Sort the
unknowns into answerable now, blocked by a named prerequisite, and needing longer observation. Use the user's supplied
questions directly. Ask only about unresolved intent or constraints that materially change the work. Discovery and
small authorized tests can proceed while those decisions are clarified.

Choose the first test that can change a decision. Prefer a native executable, direct browser, existing public API or
small configuration change. Keep the mechanism under investigation and remove unrelated setup. Start as soon as
research yields a useful lead, then alternate research and experimentation. Spend at least 10 active experimental
minutes per 60 research minutes, counting necessary narrow preparation, execution and interpretation. Each cycle must
include an executed relevant probe or direct observation. Do not wait for the hour or pad a completed investigation.
Record real blockers; setup-only work does not answer the intended feature question.

Use the [generic profile](../profiles/generic.md) unless the task selects another. For delivery, define the exact
customer journey and its required services. Classify artifact ownership and deployment placement only when they affect
that journey. For an isolated experiment, the first useful result can be a scoped observation with no deployment.

Before long work, report known actions that require the user or another owner. Name the exact missing access, source,
runtime, package publication, account scope or environment and how to verify it. Continue independent work and report
new blockers promptly. An accessible but untested option remains unknown.

Keep one [active task record](../agents/01-ae01-maintain-the-active-task-record.md): outcome, questions, options,
evidence, source, authorization, current anchor, next experiment or concrete implementation step, and continuation.
Reconcile it with the latest user message before resuming. Historical incidents guide relevant checks; they do not
create a form for every case.

The pack does not grant permission to publish packages, send messages, spend money or change a live system. Existing
authorization remains valid for the same action and destination. Do not ask for it again.
