# AE01 Maintain the active task record

Record the user's goal before implementation choices. Distinguish the requested outcome from optional improvements.
Treat a status question or clarification as steering the active task unless the user cancels it or replaces it with an
incompatible objective. Record new scope explicitly and retain the earlier completion criteria that still apply.

Use the following ordinary Markdown example in the project's existing work record. Replace every placeholder. It is a
handoff format, not executable configuration, a new required filename or a substitute for the full plan.

```markdown
## Active task

Intent and completion: [user outcome; exact acceptance journey] Required now / deferred: [scope; maintenance and
ownership decisions] Authority: [current repository rules and original guide references] Source: [repository; branch;
base and current full SHAs; remote check time] Workspace: [dirty/staged/untracked work; other writers and owned paths]
Authorization: [operation, destination, principal; instruction reference] Current milestone: [exit evidence; last
observed result; next bounded action] Acceptance: [actor, action, runtime, recipient if any, visible result] Evidence:
[passed/failed/blocked/not checked/not required; receipt links] Owner actions: [exact missing capability, owner, impact;
or none known] Parallel work: [assignment, exclusive write scope, status, integration owner] Recovery: [durable
source/checkpoint, full plan/research, pending processes] Continuation: [read first; verify current state; do next; stop
condition]
```

For each evidence receipt, name source/artifact identity, configuration identity, environment, time, command or
operation, result and limitation. Reference secrets by role or location; never copy their values. When a source or
requirement changes, mark only affected proof stale and explain why.
