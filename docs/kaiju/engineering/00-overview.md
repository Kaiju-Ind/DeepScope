# Overview

Engineering improvements must name the product consequence, such as a customer-visible delay, incorrect output or a
slower path to a reliable change. Follow [A01](../product/01-a01-start-from-the-product-question.md) before large
implementation. Use a small direct experiment to answer the next unknown, then apply the rules below to the supported
change. Choose tools from the actual project; the [generic profile](../profiles/generic.md) is the default.

**Status:** Reusable procedure, drawn from Core's CI work and the [project playbook](../start/README.md). This chapter
defines an engineering contract, not a claim that every repository has implemented the optimizations. Core-specific
tasks, Git SHAs, versions, workflow names and counts are examples, not shared defaults.
